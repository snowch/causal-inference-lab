Before you start

Read Python lists, function calls and short loops before starting. Means and proportions help; specialist statistics is not required. Work through the 18 lessons in order. Allow about eight minutes per initial investigation, plus exploration: roughly 2½ hours. These are author estimates, not learner-study results.

Scientific Method Lab introduces fair comparisons, measurement, uncertainty and reproducibility. This lab extends that reasoning to situations where you observe treatment choices rather than assign them. It is not a complete mathematical treatment or a substitute for subject knowledge.

Each lesson has a prediction, an editable complete example, a change to try and a fresh question with feedback. Read first, predict, run, change, then explain. Reading marks record progress, not mastery. The final lesson offers an exportable report.

Every dataset here is invented or simulated and labelled at use. Known potential outcomes and assignment probabilities are teaching conveniences. They are generally unavailable in real studies. No lesson establishes a real treatment effect.

Scientific methodology links a question to evidence that could challenge an explanation. Causal inference contributes explicit counterfactuals, comparison designs and identification assumptions. Reproducing an estimate checks the calculation; challenging confounding, selection and treatment definitions checks its interpretation.

Python on your device

Run starts real Python through self-hosted Pyodide 0.27.7 in a Web Worker. NumPy, SciPy, pandas and Matplotlib are pinned to the Pyodide lockfile and their downloaded wheels are hash-verified at build time. Runtime manifest. The first run downloads a substantial runtime; opening a lesson does not start Python. A connection is required for uncached assets; full offline support is not provided.

Your Python and notes are not submitted to a Python server. There is no account, analytics or application backend. User-edited Python can itself make browser-permitted network requests. Run only code you trust. Each execution starts with fresh user variables; imported modules remain loaded.

Stop ends the Python session. Select Run Python to start a new one. Initialisation has a two-minute limit and execution has a 45-second limit. An execution error appears beside the editor. Your last successful result remains available. In Tools, Restore example replaces the editor with the published code. Recover draft brings the previous code back. Ctrl+Enter or ⌘+Enter runs Python. Tab moves between controls.

Worked versus actual output

Worked output is generated by executing the exact published code during the build. Your result appears only after a browser execution. Build versions and each run export identify their respective environments. Floating-point formatting and seeded random behaviour can vary across environments. Neither output is real-world evidence when its inputs are invented.

Keep your work

Code drafts, predictions, notes, attempts, report fields and reading marks stay in this browser under cil: storage keys. Storage failures are announced. Clearing site data removes drafts. Export progress from the overview to preserve or transfer them; imports merge matching records. Theme preferences are separate.

Run exports contain the exact source, output, figures and runtime versions from the last successful execution. This record stays in memory until exported. The final report includes this run and the current report fields. It also flags changes to the editor or input since the run. Save a run JSON separately if you need figure data. A report without a successful execution records that status.

Without JavaScript you can still read all lessons, inspect published code and open worked output. JavaScript enables execution, feedback and drafts. You can download the source from GitHub and run examples locally with the repository requirements.

Key terms

Estimand
The precise target quantity: population, treatment contrast, outcome and time.
Identification
Expressing the causal estimand using observed-data quantities under explicit assumptions.
Exchangeability
For the stated population, treatment groups are comparable in their potential outcomes, possibly conditional on baseline information.
Consistency
The observed outcome equals the potential outcome for the treatment strategy actually received; treatment versions must be adequately defined.
Positivity
Each treatment has positive probability within every baseline group required by the target comparison.
No interference
One person’s outcome does not depend on other people’s treatment assignments, for the individual-treatment formulation used here.
Confounder / mediator / collider
A common cause / a variable on a causal pathway / a common effect of variables on a path. Their different roles determine whether conditioning helps.
ATE / ATT / LATE
Average treatment effect in the target population / among the treated / among compliers under the instrumental-variable assumptions.

Sources and acknowledgements

Original teaching examples build on these methodological references. Links are for further study; this is a selected reading list, not a systematic review. Source links and automated execution do not establish the course’s learning effectiveness.

  • Hernán and Robins · Causal Inference: What If — potential outcomes, exchangeability, standardisation, weighting and longitudinal reasoning.

Where to go next

This introductory route does not cover longitudinal treatment-confounder feedback, g-methods, doubly robust estimation, cluster inference, survival outcomes or formal mediation identification. Matching, discontinuity and instrumental-variable examples are deliberately simplified. Real studies need domain-specific design, diagnostics and appropriate uncertainty analysis.
